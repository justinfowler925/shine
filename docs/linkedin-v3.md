# LinkedIn draft — Shine V3

I rebuilt the wrong thing recently.

An internal work surface passed visual checks: accessible, responsive, structurally related to a real UI kit. It was still miserable to use. The screen was a status wall when the job was to decide what mattered and act on it.

That is a useful failure. A UI can have good contrast, clean components, and a familiar layout—and still make a person invent the next step.

Shine V3 changes the standard. It still uses real reference patterns from Shadcn, Untitled UI, and the broader corpus. But every surface now has to prove its primary workflow in a browser: name the objects, map them to the chosen pattern, take a real action, and show an observable result.

“Looks like the kit” is no longer enough. “The user can finish the job” is the gate.

I also removed the legacy MUI, Carbon, and Ant routing from the active path. Narrower, sharper, and easier to trust.
