# Audit: why shine V2 cannot produce useful UI (2026-08-21)

Audited artifact: the deployed skill — `~/.claude/skills/shine` and `~/.cursor/skills/shine`
both symlink to `~/Projects/shine-live/skill` on `site/v2-landing` (contains V2, `e6dff48`).
Every claim below was measured against that checkout or reproduced live; repro commands inline.

## Root cause

Shine built the **enforcement half** of a retrieval-augmented design system and **stubbed
the retrieval half**. The gates prune the model's own design priors — the only design
knowledge actually present in the loop — while the "DNA" mechanism transfers ~7 adjectives,
6 CSS variables, and 2 region names per cite. Output quality is arithmetic:
base-model priors − banned priors + transferred knowledge, with transferred ≈ 0.

## Findings

### 1. DNA packs are generated placeholders, not design

`corpus/pack.mjs` emits every `specimen.html` from four hardcoded archetypes
(table / hero / lex-record / header+paragraphs) sharing one hex palette.

- `corpus/packs/shadcn-dashboard-01/specimen.html` (1,731 bytes): a toolbar, one button,
  and two `<p>` tags printing the metadata as prose ("Density comfortable. Motion 150ms.").
  No sidebar, no cards, no chart, no table. The real dashboard-01 has six-plus regions.
- The shadcn-zinc specimen paints **IBM Carbon grays** (`#f4f4f4`/`#161616`/`#e0e0e0`) —
  the specimen contradicts its own DNA family. All families share the palette; only
  font-family string, radius, and two paddings differ (verified by diffing style blocks).
- `regions.json` for the dashboard: two regions — "header 12%" and a "focal 60%" whose
  `job` field is the copy-pasted signature string.
- `dna.json`: family / density / radius / chroma-as-two-decimals / motion — adjectives.
- Specimens carry `shine-lint: off color type shadow spacing` — **shine's own exemplars are
  illegal under shine's own lint** (see finding 5).

### 2. The one real asset is unreadable and untranslatable

- `~/design-corpus/shadcn-registry/items/dashboard-01.json`: 76,987 bytes, 100 lines,
  **longest line 28,390 chars**. The Read tool truncates long lines; the `#fragment`
  anchors `cite.mjs` prints resolve in no tool. The mandated "read every file it lists"
  is physically unsatisfiable.
- Content is React/TSX with Tailwind + shadcn semantic classes (`bg-muted/50`) whose
  meaning lives in theme CSS the cite does not list — while SKILL.md mandates
  "single-file artifacts: hand-written CSS, not Tailwind."

### 3. The vision channel is fictional

- "Open the Preview (URL or PNG) — vision is part of the cite": **zero local screenshots**
  of any cited screen exist. Six PNGs total in `~/design-corpus/query-only/`, all paid-kit
  gallery grids. Previews are JS-rendered external URLs.
- `references/direction.md` step 2: "Read both pack PNGs" — packs contain no PNGs and never have.
- `images_read` is self-reported, and `verify/critic.mjs:125` **hardcodes**
  `images_read: [specimen.html]` — fabricated evidence by construction.

### 4. The likeness gate measures self-labeling, not likeness

`verify/critic.mjs` scores likeness by regex over the HTML source: start at 10, subtract
for missing/mismatched `data-cite` / `data-dna-family` attributes plus a few string tests.

Live repro (2026-08-21): a page containing **one button** and three attributes —

```html
<html data-cite="carbon-datatable" data-dna-family="carbon" data-shine-voice="kit-faithful">
<body><button data-primary>x</button></body></html>
```

→ `critic PASS cite=carbon-datatable likeness=10 slop=none`, exit 0.

Conversely a pixel-perfect clone missing the attributes scores 3–4 and is **blocked**.
The header comment claims sharp-hashed screenshot comparison; there is no `sharp` import,
and the `--shot` branch spawns measure.mjs with `stdio: "ignore"` — result discarded.
Under the 3-pass cap, this gate trains exactly one behavior: attribute-stamping.

### 5. Kit-faithful paint is illegal under shine's own gates

- `references/voices.md`: "Semantic tokens keep their names; **values** come from the
  pack." The voice layer carries **zero colors**: `tokens/voices/shadcn-zinc.css` is a
  generic font stack + 3 radii + 2 durations; `magicui.css` — for a kit whose identity is
  gradients/glow/shimmer — is 4 radii + 2 durations + 2 font sizes; `shine.css` is an
  empty ruleset. No voice file contains a single color declaration.
- `hooks/design-lint.mjs` hard-blocks every raw hex / `rgb()` / `oklch()` in style values;
  `tokens/dist/` contains only `brand` and `personal` (house) palettes.
- Therefore Carbon blue, MUI's palette, Magic UI gradients **cannot legally be written**.
  "Apply the cite's visual DNA" compiles to: house palette + different corner radius +
  different font string + different duration. This is the mechanism behind
  "everything shine makes looks the same."

### 6. The catalog indexes what was easy, not what jobs occur

- 141 rows, 23 packs. **71 rows tagged `charts`** (Recharts/nivo/visx demo inventory);
  `settings`=2, `crud`=2, `wizard`=2, `chat`=2, `checkout`=1, `email`=1, `blog`=1.
- Job lexicon is 26 exact-match tokens: `cite.mjs "settings page"` → error.
- All 9 `lex-*` rows and both `shine-*` rows have `path` pointing at **shine's own
  generated packs** — self-citation; no real SLDS example anywhere in the loop.
- A missing row triggers the `inspiration.md` protocol: research pages, author a
  templates.json row, re-cite — a mandatory detour ending in a row with no pack (a label).

### 7. The executor is split-brained across two checkouts

`agents/shine-ux.md:13,29,64-65` and `SKILL.md:248` hardcode `~/Projects/shine` — a
worktree of this same repo, **26 PRs behind, pre-V2**, on `justin-fowler/sled-capture-saas-ui`,
dirty. Run from there:

- `cite.mjs dashboard` answers **tremor-dashboard** (different catalog) with the retired
  banner "Paint: shine tokens. Structure cloned; vendor pixels are not" — the exact
  sanding doctrine V2's agent file bans.
- `verify/critic.mjs` and `corpus/packs/` **do not exist there** — the mandated critic
  step and pack read fail with ENOENT mid-loop.

### 8. Ceremony-to-payload ratio

Mandatory before drawing one pixel: SKILL.md (16.4KB) + direction.md + diagnose.md +
voices.md + 5 pack files + every cite-listed file (77KB unreadable JSON) + contracts.md
when a Table/Form is named + adoption.md when internal ≈ **35–40k tokens of process**.
Transferable design knowledge inside all of it: the adjectives and six variables of
finding 1. Then the slop classes and "2026 defaults" ban zinc/Geist, indigo, purple
gradients, cream+serif — the aesthetics the base model executes most reliably — leaving
one fully-specified look in the system: house style. Which is what comes out.

## What is genuinely sound (keep)

- `verify/measure.mjs`: real — Playwright render, axe, per-pixel contrast, void/composition
  checks, the Carbon table-area check.
- The token pipeline and house/brand lanes; design-lint/stop-sweep/doctor wiring.
- `contracts.md` (completeness ladder), `adoption.md` (ritual-first doctrine),
  `salesforce.md` (measured org facts), the corpus pins themselves (1.2GB of real source).

All of it verifies **compliance and completeness**. Nothing in the system can make a
screen look like anything in particular; the parts that were supposed to — packs, voices,
critic, previews — are stubs wearing load-bearing names.
