# Source-bound route and state audits

Run the census before authoring a contract:

```
node integrations/surface-audit.mjs --project /path/to/product
```

A version 1 contract contains `buildHeader` (the deployed source SHA header), `widths`
(default 390 and 1440), `routes`, and `controlOwners`. Every discovered Next App Router
page must appear at least once. Route variants may share a source but have distinct ids.
Each route has an id, source, same-origin URL, requiredStates, and states. Each state has
an id, optional same-origin path, and browser steps using the existing usability DSL:
click, fill, press, select, visible, hidden, text, value, checked, count, enabled, disabled.
Every state needs an observable assertion; non-ready states also need a user action.

Each control owner names its source, a specific reason, and proofs with route/state ids.
The verifier resolves the consumer's TypeScript aliases and parent layouts and rejects
an owner whose proof route cannot import that source. A source imported on a page still
needs an appropriate workflow: import reachability is not a semantic assertion that every
control was exercised. Review requiredStates against the actual workflow before execution.

Use `ready` only for baseline route readiness. Search, save, validation, denied access,
empty, error and recovery scenarios must be declared separately when those jobs exist.
For routes behind permissions, use the applicable private storage state and separate runs;
do not weaken route outcomes to make an unauthorized session pass. Keep auth files private.

Run against a clean source checkout. The application must expose its full Git SHA in the
configured response header. Authentication redirects, HTTP failures, runtime exceptions,
page overflow and mismatched build identity fail. The generated receipt binds source files,
CSS/config/dependencies, the exact contract, commit, widths and all route/state results.

```
node integrations/surface-audit.mjs --project /path/to/product \
  --contract shine-surfaces.json --run https://product.example \
  --storage-state /private/session.json --out /private/surface-proof.json
node verify/prove.mjs ... --surface-contract shine-surfaces.json \
  --surface-receipt /private/surface-proof.json
```

Receipts are generated by the runner, never hand-authored. The default freshness window
is 24 hours; changed source or contracts require a rerun even within that window. Overall
completion remains exclusively issued by `verify/prove.mjs` after its other gates pass.

Current automatic route discovery targets Next App Router pages. Other routers require
an adapter before this verifier can claim whole-site coverage; an empty route population
fails rather than being treated as completion.
